# Prior art and evidence

Research date: 2026-09-08. Deep, read-only research across repository, local skills, native facilities, current-stack libraries, adjacent implementations and protocol references.

Repository refresh: 2026-09-11 against main `3d7c673`, recorded in [the baseline ledger](11-main-refresh.md). The external candidate/license research below retains its September 8 date and revisions; this refresh did not repeat that whole survey. Current official Codex subagent/worktree guidance was checked for the [agent implementation plan](10-agent-orchestration.md). Exact dependency releases still require validation when adopted.

Our existing adapters and native Windows/.NET facilities cover much of the engine migration. Discord.Net is the best supported current-stack Discord candidate found. Agent Secret supplies the closest permissive reference for agent-requested secret consent, while Joydex still needs its own attribution and four-choice rules.

**What I'd do:** use ENGINEFIRST + KEEPFORMS, the existing integration adapters, and narrow native services. Evaluate StreamJsonRpc as the worker/client transport and Discord.Net for Discord. The Secrets implementation evaluated DotNetEnv 3.2.0 and retained a strict local parser after its resolved dependency graph failed repository package-audit policy. Use OpenClaw and Agent Secret primarily as contract/test references. Keep private Desktop interoperability behind a capability gate.

**Search note:** Independent lanes covered Discord/Desktop, secrets/consent and local device/media ownership. The final expansions into alternative C# transports, native Desktop relays, generic agent protocols, vault frameworks and authorization models produced no verified complete Windows solution for the combined requirements. The remaining gaps are installed Desktop external creation and verified task origin, plus runtime/hardware behavior that requires an implementation canary.

## Other leads and exclusions

- NetCord at [ffb28e1c, MIT](https://github.com/NetCordDev/NetCord/blob/ffb28e1cf5d71a9e90d1eed866961bfec8acfeac/LICENSE.md) and DSharpPlus at [d23f8e19, MIT](https://github.com/DSharpPlus/DSharpPlus/blob/d23f8e1908e34c0cd89535289743c993662986ff/LICENSE) are viable component families. Evaluated mainline targets net10.0/net9.0; older compatible packages could change fit, but no advantage currently justifies changing our SDK.
- [codex-mobile](https://github.com/NathanZane/codex-mobile) has [MIT source at f79e6807](https://github.com/NathanZane/codex-mobile/blob/f79e6807ca0b9d6052afd24f822ee41b9a52e07d/LICENSE). Its private IPC/approval code is a reference; broad existing-task mirroring differs from our scope.
- [codex-discord-remote](https://github.com/simdorei/codex-discord-remote) at d1c23726e02ef95d67e9789975aa693c6846818b lacked a clear license in the inspected root/API. STUDY-ONLY; no code copied.
- [ACP session setup](https://agentclientprotocol.com/protocol/v1/session-setup) is a useful protocol comparison; it does not establish connection to Codex Desktop's saved projects or writer.
- AssemblyLoadContext supplies dependency loading, not a security sandbox. Explicit bundled factories and worker processes cover our first release without dynamic DLL discovery.
- Windows Hello can verify the local person for a later unlock policy. It does not implement YES_ALWAYS/YES/NO/NEVER or project/task grant matching.
